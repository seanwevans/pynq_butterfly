## Boundary of this checkpoint

The FPGA performs:

```text
c0 = a0*b0
c1 = a0*b1 + a1*b0
c2 = a1*b1

ks_b = sum_j digit_j * eval_key_b_j
ks_a = sum_j digit_j * eval_key_a_j

relin_c0 = c0 + ks_b mod q
relin_c1 = c1 + ks_a mod q
```

The BV digits are generated by OpenFHE on the host from `c2`. Moving CRT
decomposition onto the FPGA remains a later NTT/basis-conversion stage.

## External protocol

### `RLPF`

```text
word 0: duplicated 0x524C5046
word 1: {q1, q0}
word 2: {mu1, mu0}, TLAST
```

The wrapper loads the same profile into both inner arithmetic engines.

### `RLBV`

```text
word 0: duplicated 0x524C4256
word 1: {digit_count, ciphertext_count}

for each ciphertext and coefficient:
    a0
    a1
    b0
    b1

    for each digit:
        digit
        eval_key_b
        eval_key_a
```

The final `eval_key_a` word carries input `TLAST`. Output is only
`relin_c0`, `relin_c1`; the final `relin_c1` carries output `TLAST`.

At the observed 12-digit BV configuration, the external input uses 40 words
per coefficient:

```text
4 EvalMul3 operands + 12 * 3 BV words
```

This first fused stream sends evaluation-key values with every coefficient.
The production transport design should cache or separately stream the
9 MiB evaluation key rather than replicate it per ciphertext.
